# OSINT Discovery Playbook — MyWave Travel

Статус: canonical operating guide for discovery/scouting  
Дата: 2026-09-29

## 1. Назначение

OSINT в MyWave Travel — не отдельный отчет и не механизм автоматической публикации. Это supply-engine, который непрерывно находит потенциальных организаторов, школы, гидов, кэмпы, клубы, события и источники программ.

Канонический путь:

```
OSINT discovery
  -> SourceProposal (pending)
  -> ручная проверка
  -> approve
  -> Source (inactive)
  -> пробный collection run
  -> RawItem
  -> NormalizedItem
  -> EventCandidate
  -> moderation / dedup
  -> Program draft
  -> publish gate
  -> operator decision
```

Найденный в интернете объект НИКОГДА сам по себе не становится Verified/Trusted и не публикуется автоматически.

## 2. Что искать

Типы:
- туроператоры и организаторы экстремальных путешествий;
- школы, кэмпы, bootcamp и clinics;
- коммерческие гиды и инструкторы;
- спортивно-туристические клубы;
- события и фестивали;
- локальные social-first команды без сильного сайта.

Дисциплины:
альпинизм, фрирайд, хели-ски, backcountry, ski-tour, сноуборд, горные лыжи, серфинг, вейкборд, вейксерф, вейкским, кайтсерфинг, виндсерфинг, SUP, скалолазание, парапланеризм, парашютный спорт, рафтинг, каякинг, фридайвинг, MTB, эндуро, трейлраннинг и смежные outdoor-направления.

## 3. Источники

Приоритет доказательств:
1. официальный сайт организатора;
2. официальный региональный туристический портал;
3. Единый федеральный реестр туроператоров Минэкономразвития;
4. реестры инструкторов-проводников/федераций, когда применимо;
5. Telegram/VK/Instagram организатора;
6. агрегаторы туров;
7. независимые отзывы/карты;
8. отраслевые медиа и события.

Важно: старую формулировку «реестр Ростуризма» в новых исследованиях заменять на актуальный Единый федеральный реестр туроператоров Минэкономразвития. Ростуризм как ведомство больше не является текущим владельцем реестра.

## 4. Две стадии качества

### Stage A — Discovery candidate
Минимум:
- название;
- рабочий публичный URL;
- регион;
- тип;
- дисциплины;
- минимум один evidence URL;
- OSINT score 1..5.

Именно такие объекты можно импортировать в SourceProposal.

### Stage B — Enriched organizer profile
Перед повышением доверия или коммерческим outreach требуется по возможности:
- ключевая персона и роль;
- юридическое лицо / ИП / самозанятый;
- ИНН/ОГРН и реестровый номер, если применимо;
- контакты;
- история и регулярность программ;
- независимые отзывы;
- партнеры/спонсоры;
- квалификации гидов/инструкторов;
- условия отмены, договор и платежный контур;
- media evidence.

Отсутствующее поле фиксируется как «не подтверждено», а не угадывается.

## 5. OSINT score

5 — официальный сайт + реестр/юрданные + действующие программы + контакты + дополнительные подтверждения.  
4 — официальный сайт/региональный каталог + действующие программы, но часть юридических/репутационных данных требует обогащения.  
3 — активный частный организатор/школа с понятным продуктом, но слабее юридическая или независимая доказательная база.  
2 — разовый или слабо подтвержденный источник.  
1 — сигнал, требующий серьезной проверки.

OSINT score — это качество разведданных, НЕ рейтинг качества организатора и НЕ safety score.

## 6. География

Первая контрольная волна:
- Камчатка — 10;
- Алтай — 10;
- Приэльбрусье — 10.

Далее: Шерегеш, Красная Поляна/Сочи, Архыз/Домбай, Хибины/Кировск, Байкал/Иркутск, Карелия, Кольский полуостров, Дагестан, Сахалин, Курилы, водные и urban-направления.

## 7. Регулярный operating rhythm

Еженедельно:
1. discovery новых источников;
2. dedup против Source + pending SourceProposal;
3. enrichment top candidates;
4. Owner review;
5. одобрение только подходящих SourceProposal;
6. один пробный collection run;
7. оценка качества нормализации;
8. только затем активация расписания источника.

Ежемесячно:
- coverage по регионам/дисциплинам;
- доля SourceProposal -> approved Source;
- доля Source -> useful EventCandidate;
- duplicate/noise rate;
- доля карточек с достаточной provenance;
- organizer linkage coverage.

## 8. Команды

Проверить пакет без записи в БД:

```bash
pnpm --filter api exec tsx prisma/import_source_proposals.ts prisma/source_proposals_osint_2026-09-29.json
```

После ручной проверки Owner — импортировать как pending proposals:

```bash
pnpm --filter api exec tsx prisma/import_source_proposals.ts prisma/source_proposals_osint_2026-09-29.json --apply
```

Импорт НЕ активирует источники, НЕ запускает сбор и НЕ публикует программы.
