# Полнота каталога: программы по запросу

Цель: не схлопывать разные `on_request` программы по placeholder-датам.

Изменены только frontend helper и существующий набор catalog tests. Поездки по запросу сохраняются по ID; повтор одного ID по-прежнему схлопывается. Поведение подтверждённых дат не меняется. БД, статусы и оригинальные медиа не изменяются.

Проверка: `pnpm run test:web:ux`, `pnpm --filter web build`, CI exact SHA. Read-only сравнение того же API payload до/после: число записей API и результат frontend helper, без публикации данных.

Риск: реальные дубли среди on-request записей теперь видны до ручного объединения; это безопаснее потери разных туров. Этот фикс не утверждает, что все dated коллизии доказанно являются дублями.

Перед deploy: CI, сравнение количества на сайте с тем же API snapshot, проверить программы БЕАРТРО по озеру/Вачкажцу/культуре отдельно. API данные могут меняться во время ingestion.

Rollback: revert PR / предыдущий web artifact, миграций нет. Независим от PR #158; новый Mini App автоматически использует этот helper после интеграции.
