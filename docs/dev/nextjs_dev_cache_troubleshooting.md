# Next.js dev: битый кэш и ошибки `Cannot find module './xxx.js'`

Операционная памятка для локальной разработки в монорепозитории (приложение `apps/web`).

## Симптом

В dev-режиме (`pnpm --filter web dev`) при открытии `localhost:3000` или при навигации Next.js падает с ошибкой вида:

```text
Error: Cannot find module './483.js'
```

Стек часто указывает на что-то вроде:

```text
apps/web/.next/server/webpack-runtime.js
```

Число в имени файла (`483`, `962` и т.д.) может меняться между запусками.

## Вероятная причина

Чаще всего это **не ошибка исходного кода** и **не связано с markdown в `docs/`**, если эти файлы не импортируются в бандл `web`.

Типичный сценарий: каталог **`apps/web/.next`** содержит **устаревшие серверные чанки** после смены ветки, обновления зависимостей или прерванной сборки — **рассинхрон chunk map** в dev.

Подтверждение: если после **полного удаления** `apps/web/.next` команда **`pnpm --filter web build`** проходит с `exit_code: 0`, production-сборка в репозитории в порядке; проблема локализуется в **dev / локальном build state**.

## Что сделать в первую очередь

1. **Полностью остановить** dev-сервер (`Ctrl+C` в терминале, где запущен `web dev`).
2. При необходимости завершить **лишние** процессы Node, которые держат старый сервер (осторожно: не завершать чужие процессы на машине).
3. **Удалить артефакты кэша** из корня репозитория:

   - `apps/web/.next` — обязательно;
   - `.turbo` — если используется Turbo и были странные артефакты;
   - `node_modules/.cache` — при подозрении на кэш инструментов.

   **PowerShell** (из корня репозитория):

   ```powershell
   Remove-Item -Recurse -Force apps\web\.next -ErrorAction SilentlyContinue
   Remove-Item -Recurse -Force .turbo -ErrorAction SilentlyContinue
   Remove-Item -Recurse -Force node_modules\.cache -ErrorAction SilentlyContinue
   ```

4. Пересобрать конфиг монорепо и снова поднять dev:

   ```bash
   pnpm --filter @mywave/config build
   pnpm --filter web dev
   ```

Если после этого ошибка **исчезла** — причину можно считать **устаревшим локальным `.next` под dev**.

## Если не помогло — второй уровень очистки

1. Остановить все связанные с проектом процессы Node.
2. Удалить **`node_modules`** в корне (и при необходимости в workspace по политике команды).
3. Установить зависимости заново и прогнать сборку:

   ```bash
   pnpm install
   pnpm --filter @mywave/config build
   pnpm --filter web build
   pnpm --filter web dev
   ```

## Если после чистой сборки ошибка сохраняется

Соберите **диагностический пакет** (без этого дальше только гадание):

1. **Полный вывод** терминала для:

   ```bash
   pnpm --filter web build
   ```

2. **Полный стек** из терминала при падении **`pnpm --filter web dev`**.
3. Явно указать: **удаляли ли** каталог `apps/web/.next` **непосредственно перед** воспроизведением.

Дополнительно проверить последние изменения в:

- `apps/web/src/app/layout.tsx`
- `apps/web/src/app/page.tsx`
- `apps/web/next.config.*`

И убедиться, что **нет прямых импортов** файлов из `docs/...` или сырых `.md` в runtime web (такие импорты должны идти через поддерживаемый pipeline, например MDX с явной настройкой).

## Windows: путь с кириллицей и пробелами

На Windows иногда встречаются **редкие** сбои инструментов сборки или кэша, если проект лежит в «тяжёлом» пути (кириллица, длинный путь, сетевой диск).

Если проблема **повторяется стабильно** даже после:

- удаления `apps/web/.next`,
- очистки `node_modules/.cache` / `.turbo`,
- полного `pnpm install` и успешного `web build`,

имеет смысл **временно** клонировать репозиторий в **короткий ASCII-путь** без кириллицы и пробелов (например `F:\Projects\MyWave\Toutism`) и повторить шаги из раздела «Что сделать в первую очередь». Если там всё стабильно — зафиксировать это в тикете как сигнал к проверке окружения.

## Краткая рабочая гипотеза

Пока `pnpm --filter web build` после удаления `.next` проходит успешно, а dev падает со `Cannot find module './xxx.js'` до очистки — **приоритетная гипотеза: локальный dev-кэш / chunk map в `.next`**, а не обязательная поломка кода в репозитории.
