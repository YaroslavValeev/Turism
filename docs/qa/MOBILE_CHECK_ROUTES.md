# Android review (Redmi и др.) — тот же минимальный набор URL

База для телефона в одной Wi‑Fi сети с ПК: **`http://<IPv4_ПК>:3000`** (web), при необходимости **`http://<IPv4_ПК>:3002`** (admin). Подробности сети и брандмауэра: [`docs/deployment/PRE_DEPLOY_LOCAL_AND_MOBILE.md`](../deployment/PRE_DEPLOY_LOCAL_AND_MOBILE.md).

Полный список путей совпадает с [`BROWSER_CHECK_ROUTES.md`](./BROWSER_CHECK_ROUTES.md) — ниже только **порядок** и **фокус** для мобилки.

## Порядок проверки

1. **`/`** — сначала главная: лендинг и каталог должны грузиться с телефона.
2. **`/program/<id>`** — одна карточка: скролл, медиа, кнопки/ссылки.
3. **Организатор (выборочно)** — например `/organizers/analytics`, `/organizers/program`: широкие блоки и таблицы на узком экране.
4. **Админка** (если нужна мобильная приёмка бэк-офиса): `/login` → `/sources`, `/event-candidates` — таблицы часто «ломают» вёрстку по ширине.

## Критично

- Данные с телефона: `NEXT_PUBLIC_API_URL` в env для `web` должен указывать на хост, **доступный с телефона** (часто IP ПК в LAN, например `http://192.168.x.x:3001`), иначе браузер на телефоне обратится к `localhost` самого телефона и каталог будет пустым/с ошибками.
- Один Wi‑Fi, правило брандмауэра Windows для входящих на порты 3000–3002 (или используемый порт web).

## Где чаще всего визуальные проблемы

- Длинный скролл главной `/`, плотные карточки.
- Шапка / меню — hit-area для touch.
- Таблицы в `/organizers/*` и в админке (`/raw-items`, `/event-candidates`) — горизонтальный overflow, мелкий текст.

## Альтернатива без LAN

Туннель к dev-серверу (ngrok, Cloudflare Tunnel и т.п.) — открыть выданный HTTPS URL с телефона; для API может понадобиться второй туннель или публичный staging.
