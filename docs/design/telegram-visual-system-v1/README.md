# Telegram Visual System v1 — гайд для команды контента и разработки

Канон оформления Telegram-канала MyWaveTour (версия 1.0 от 01.10.2026, утверждён Product Owner).
Источник истины — [`canon/MyWaveTour_Telegram_Visual_System_v1_CANON.pdf`](canon/MyWaveTour_Telegram_Visual_System_v1_CANON.pdf).
Задача для команды — [`canon/Implementation_Brief_Tour_Team_v1.pdf`](canon/Implementation_Brief_Tour_Team_v1.pdf).
При конфликте между референсами и каноном прав канон: на референсах демонстрационные тексты, цифры и UI-состояния.

| Файл | Что это |
|------|---------|
| `references/Reference_A_Adventure_Magazine_Aqua.png` | Основной режим **Aqua** (по умолчанию, ~70–80% публикаций) |
| `references/Reference_B_Premium_Dark_Editorial.png` | Дополнительный режим **Dark** (редакционный акцент, ~20–30%) |
| `apps/web/public/brand/mywavetour-logo-official.png` | **Официальный логотип** — единственный исходник знака |
| `services/api/src/modules/telegram/visualSystem.ts` | Токены, размеры экспорта, рубрики, альбомы, манифест ассетов, имена файлов |

Токены Telegram (`#0CC7D4` Aqua и др.) **не** применяются к сайту: у сайта своя палитра в `apps/web/src/app/globals.css`.
Изменения ядра (логотип, палитра, шрифт, рубрики, роль Aqua/Dark) — только новой версией канона (v1.x / v2.0) с approve владельца.

## Как собрать публикацию

1. **Данные.** Берём карточку программы MyWaveTour или тему редакционного поста. Даты, цена, уровень, риск, состав услуг — только из карточки/источника организатора. Выдумывать нельзя; нет поля — блок не выводится.
2. **Рубрика** (одна из 8): `DESTINATION` · `CAMP` · `DROP` · `GUIDE` · `PEOPLE` · `STORY` · `COMPARE` · `SAFETY`.
3. **Режим.** Aqua по умолчанию. Dark — только по основанию: safety, ночные/драматичные сцены, backstage, экспедиции, премиальные подборки (`SAFETY` по умолчанию Dark).
4. **Фото.** Реальное медиа организатора/поездки, не сток. Проверить права, качество, вертикальный crop, спокойную зону под заголовок.
5. **Обложка** из master-шаблона: label рубрики + короткий заголовок (1–2 строки) + максимум 1–3 параметра. Логотип меньше заголовка.
6. **Текст** — нативный Telegram: короткий лид → параметры → полезные детали → CTA.
7. **Кнопки** — реальные inline-кнопки (не нарисованные на картинке).
8. **Проверка**: превью на ширине смартфона, светлая и тёмная тема Telegram, после сжатия Telegram.

### На обложке нельзя

Длинный прайс, «входит/не входит», телефоны, QR, программа по дням, юридические условия, псевдокнопки,
выдуманные просмотры/отзывы/даты/цены, случайные градиенты и неон, одинаковая рамка на каждом посте,
перерисованный или «похожий» логотип.

## Размеры экспорта

| Формат | Размер | Правило |
|--------|--------|---------|
| Пост (feed / editorial) | 1080×1350 (4:5) | Поле 48–64 px, текст в safe zone |
| Story / обложка альбома | 1080×1920 (9:16) | Верх и низ свободны под интерфейс Telegram |
| Аватар | 1080×1080 | Круговая маска, свободный край ≥12% диаметра, читаемость на 40–48 px |
| Видео вертикальное | 1080×1920 | Из того же key visual, что и горизонтальное |
| Видео горизонтальное | 1280×720 | |

Сетка 8 px (8 / 16 / 24 / 32 / 48 / 64), радиусы 16–24 px только для UI-карточек. Шрифт **Inter**:
заголовки Bold/ExtraBold, подзаголовки SemiBold, текст Regular, цифры/метки Medium.

## Имена файлов

Генерируются `telegramExportFileName()` в `visualSystem.ts`:

- пост — `tg_post_<rubric>_<slug>_<YYYYMMDD>_vNN.png` (например `tg_post_camp_kamchatka-powder_20261001_v01.png`);
- story — `tg_story_<album>_<slug>_<YYYYMMDD>_vNN.png`, альбомы: `camps`, `freeride`, `wake`, `enduro`, `guides`, `people`, `reviews`, `tips`;
- видео — `tg_video_<slug>_<vertical|horizontal>_vNN.png`;
- бренд — `tg_brand_avatar_vNN.png`, `tg_brand_wallpaper_<light|dark>_vNN.png`.

Slug — латиница, цифры, дефис. Master-шаблоны хранятся отдельно от экспортов; версии — через `vNN`, не через копии `final_final2`.

## Автопост программы в канал (что уже делает код)

Публикация при переходе программы в `published`: `services/api/src/modules/subscriptions/notifier.ts`.

- **Текст**: «Новый вызов от …», заголовок, даты и длительность, место и дисциплина, строка
  `Уровень · Риск · от <цена>` (только заполненные поля), «Для кого», «Что входит», организатор, «Перед бронированием», «Как записаться».
  Пустой блок скрывается целиком, заглушек нет. Если текст не влезает в подпись к фото (1024 символа), берётся компактный вариант.
- **Кнопки** (`services/api/src/modules/telegram/channelClicks.ts`):
  - «Программа» → карточка на сайте (`utm_content=program`);
  - «Задать вопрос» → адрес из `TELEGRAM_CHANNEL_ASK_URL` (Direct Messages канала или менеджер); без переменной кнопка не выводится;
  - «Оставить заявку» → форма заявки на карточке (`#request`, `utm_content=apply`).
- **Учёт кликов**: каждая кнопка ведёт через `GET /public/tg/c/:token` (запись в `telegram_clicks`, событие `channel_cta_clicked`, redirect).
  После публикации клики привязываются к `message_id` поста (`sourcePostId`). Если API не публичный или БД недоступна — кнопки ведут напрямую.

## Ручная настройка канала (делает владелец/админ, не код)

Сначала скриншоты текущего канала, затем — только после визуального approval владельца:

- аватар 1080×1080 из официального логотипа (светлый вариант первым);
- описание: «Спортивные путешествия, кэмпы и экспедиции. Фрирайд, вейк, эндуро, MTB и другие дисциплины. Проверенные организаторы, понятные программы, реальные истории. ↓ Найти следующий выезд»;
- Appearance (profile color, logo, wallpaper light/dark) — если уровень канала позволяет; иначе ничего не имитируем;
- Direct Messages — включить после назначения ответственных и SLA; адрес прописать в `TELEGRAM_CHANNEL_ASK_URL`;
- Welcome Message: что такое MyWaveTour + «Найти поездку», «Выбрать дисциплину», «Задать вопрос»;
- Stories / Albums (при доступности): КЭМПЫ, ФРИРАЙД, WAKE, ЭНДУРО, ГИДЫ, ЛЮДИ, ОТЗЫВЫ, ГАЙДЫ/СОВЕТЫ;
- группа обсуждений: единое название/аватар, правила, модерация.

## Рендер обложек

`services/api/src/modules/telegram/coverRenderer.ts` — `renderCoverPng(input)` (satori → resvg, шрифт Inter latin + cyrillic):

- с фото: фото на весь кадр + градиент режима (Aqua — бирюзовый, Dark — night);
- без фото: фирменная топографическая сетка (`topographicSvg`), заголовок до 2 строк, до 3 параметров;
- COMPARE: две карточки сравнения; формат `post` (1080×1350) или `story` (1080×1920).

Фото перед рендером проходят `photoEnhance.ts` (sharp): кроп по центру под формат, автоуровни, +10% насыщенности,
резкость. Если фото пришлось бы растянуть больше чем в 3 раза (например, 180×320) — обложка делается типографской.

Задание дизайнеру на недостающие ассеты: [`DESIGNER_TASK.md`](DESIGNER_TASK.md).

## Сэмплы и тестовые публикации

```bash
# 8 обложек по рубрикам + аватар + обои → exports/ (данные берутся из публичного API прода, ~3 мин)
pnpm --filter ./services/api exec tsx scripts/telegram-visual-samples.ts

# публикация из exports/manifest.json: по умолчанию владельцу в личку (TELEGRAM_CONTENT_OWNER_CHAT_ID)
pnpm --filter ./services/api exec tsx scripts/telegram-visual-publish.ts [--only CAMP,DROP] [--dry-run]
# в боевой канал (TELEGRAM_UPDATES_CHANNEL_CHAT_ID) — только с явным подтверждением
pnpm --filter ./services/api exec tsx scripts/telegram-visual-publish.ts --target channel --yes
```

Кнопки сэмплов ведут на сайт напрямую (`utm_medium=visual_system_v1`); трекинг через `/public/tg/c/:token`
включается в автопосте после деплоя API. Результат публикации — `exports/publish-log.<target>.json`.
