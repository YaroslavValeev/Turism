# Stage 4.1+ — guardrails для статусов

## Правило по умолчанию

1. **Правила переходов** — только в `packages/shared-policy` (или явно импортируемых из него контрактах).
2. **Запись статуса в БД** в доменных сущностях (program, booking, intake, organizer verification, commission reconciliation и т.д.) — только через **`services/api/src/modules/status-engine`** (`apply*`) либо через **узко описанные** исключения ниже.

## Исключения (не норма, а учёт долга)

Точки из **`STAGE4_1_DIRECT_STATUS_WRITES.md`** — закрытый контур учёта долга: список можно **только сужать** (убирать прямые записи по мере переноса в engine), **расширять** — только с явным решением владельца и ADR. Новая фича **не** добавляет сюда строку без ADR и обновления списка.

## Code review чеклист

- [ ] Нет нового `prisma.*.update({ data: { …Status` без прохождения policy/engine.
- [ ] Если исключение неизбежно — есть ссылка на ADR и запись в direct-writes.
- [ ] Для auto-действий есть `triggerMode: "auto"` в `DomainStatusEvent` (где применимо).

## Цель

Не вернуться к «статус в трёх модулях с тремя матрицами».
