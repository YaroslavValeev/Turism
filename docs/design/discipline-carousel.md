# MyWaveTour: карусель дисциплин

## Цель и границы

На главной спокойная карусель скульптурных фигурок позволяет узнать дисциплины и перейти к существующим программам. По уточнению владельца от 2026-10-16 блок расположен сразу под логотипом, перед выбором роли, фильтрами, hero и кинолентой. Шапка получает необязательный слот `afterBrand`; в него передаётся существующая карусель. Основной CTA, каталог, формы, API, маршруты и отправка заявок сохраняются.

Это CSS-карусель с прозрачными изображениями 3D-скульптур, без WebGL и новых зависимостей. Сцена занимает всю ширину экрана, заголовок и управление остаются в обычной сетке страницы. На широком экране дуга показывает больше соседних фигур вместо растягивания пустых промежутков; ширина центральной фигуры адаптируется от 216 до 280 px. На мобильном шаг между центрами не превышает 92 px. Применены смещение по оси Z, перспектива, масштаб и контактные тени; отдельных подписей-карточек нет, подпись и ссылка центральной фигурки вынесены под сцену. Утверждённые изображения не меняются.

## План и функциональные инварианты

1. Прочитать промпт и HTML; проверить зависимости, Docker, БД и публичный API.
2. Изолировать изменения в отдельной ветке и рабочей копии.
3. Создать скульптуры и компонент с локальным состоянием отображения.
4. Передать компоненту существующие `disciplineOptions` и ссылки из `catalogHrefBuilder`.
5. Проверить управление, адаптивность, типы, существующие UX-тесты и сборки.

Источник списка — существующий `disciplineOptions`, полученный из программ каталога. По прямому замечанию владельца `wildlife / дикая природа` исключён из визуального выбора карусели; данные API и сам каталог не редактируются. Остальные названия и значения query-параметров не заменяются. Каждая ссылка создаётся существующим `catalogHrefBuilder({ discipline: label })`. Автовращение, стрелки, свайп и колесо меняют только центральную фигурку; фильтр применяется при переходе по ссылке, как у существующих ссылок дисциплин. Новых программ, дисциплин, дат, цен или trust-сигналов нет.

## Скорость и управление

Существует распространённый default **5000 мс** между слайдами: [Splide](https://splidejs.com/guides/options/#interval), [Bootstrap](https://getbootstrap.com/docs/5.3/components/carousel/#options). Это проверяемый ориентир, а не статистическое доказательство самой популярной скорости. У Splide default перехода — 400 мс.

По новому запросу владельца для MyWaveTour выбрано **4000 мс между поворотами** и **650 мс на переход**. Между плавными переходами остаётся время на распознавание фигурки и подписи. Полный цикл равен числу доступных дисциплин, умноженному на 4 секунды; скорость не зависит от их числа.

- Колесо: одна дисциплина на импульс; порог 32 px и защита от инерции 700 мс. На первом/последнем элементе вертикальное колесо продолжает прокрутку страницы. Ctrl/Meta + колесо сохраняет zoom.
- Горизонтальный свайп/drag: движение следует жесту; отпускание переключает одну дисциплину. Вертикальная прокрутка страницы и pinch zoom сохраняются. После drag ссылка не открывается случайно.
- Клавиатура: ←/→, Home/End, обычные Tab/Enter и видимый focus. Отдельные стрелки имеют цель 44×44 px.
- Автовращение включено по умолчанию. Наведение мыши временно приостанавливает его; сенсорный ввод не создаёт зависшую паузу наведения. После колеса, свайпа или клика по стрелке вращение возобновляется через 8 секунд бездействия, когда указатель находится вне блока.
- Клавиатурный фокус останавливает вращение до явного нажатия «Продолжить». Кнопка «Пауза» сохраняет остановку независимо от таймера возобновления.
- Вне видимой области и при скрытой вкладке таймер останавливается. При `prefers-reduced-motion: reduce` отсутствуют автоповорот и transitions.
- Объявления screen reader отключены во время автоповорота, включены для ручного выбора. За пределами видимой дуги нет доступных для Tab ссылок.

Поведение фокуса и управления следует [WAI Carousel Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/carousel/).

## Изменённые файлы

- `apps/web/src/app/home-page.tsx`: подключение компонента в слот шапки; существующая логика не изменена.
- `apps/web/src/components/SiteHeader.tsx`: необязательный слот `afterBrand` сразу после логотипа, перед ролью и фильтрами.
- `apps/web/src/components/DisciplineCarousel.tsx`: представление, локальное вращение и жесты.
- `apps/web/src/components/DisciplineCarousel.module.css`: изолированные стили; используются существующие `--mw-*` tokens. Локальный motion token — `--carousel-transition: 650ms`. Сцена выходит за внутренние отступы шапки без `100vw`, чтобы не создавать горизонтальную прокрутку из-за scrollbar.
- `apps/web/public/media/disciplines/*.webp`: wakesurf, ski-alpine-v2, ski-tour, freeride-snowboard, heli-ski-ka62-baskets, kite, mtb, trekking, climbing, snowmobile, expedition. Предыдущие варианты сохраняются для истории; в текущем UI используются только перечисленные файлы.
- `docs/design/discipline-carousel-assets.json`: полный набор промптов; генерация встроенным imagegen, alpha сохранена при подготовке WebP.

Одиннадцать используемых файлов имеют размер 400×440 px; общий объём — около 473 KB. Изображения выбираются по уже существующим названиям. Неопределённая дисциплина сохраняет исходное название и получает нейтральный компас.

Замечания владельца к фигуркам учтены:

| Направление | Текущее изображение |
| --- | --- |
| Горные лыжи | Лыжник в комбинезоне, без рюкзака |
| Ски-тур | Человек поднимается по склону, лыжи закреплены за спиной |
| Фрирайд / скитур и варианты названия фрирайда | Сноубордист в вираже, с рюкзаком |
| Хели-ски | Вертолёт по присланному фотореференсу, с колёсным шасси и закрытым хвостовым винтом; наружная корзина с лыжами на двух подвесах добавлена в отмеченной области |

После принятия трёх спортивных фигурок менялось только изображение вертолёта. SHA-256 принятых `ski-alpine-v2`, `ski-tour`, `freeride-snowboard` сверены и не изменились. Новый фотореференс определяет форму и колёсное шасси вертолёта; последующее замечание определяет открытую корзину для лыжного снаряжения. Изображение остаётся иллюстрацией дисциплины, не утверждением об оборудовании конкретного организатора.

## Локальная проверка

Команды выполняются из корня отдельной рабочей копии, локально в PowerShell:

```powershell
pnpm install --frozen-lockfile
pnpm --filter web exec tsc --noEmit
pnpm run test:web:ux
pnpm --filter web build
pnpm run dev:web
```

Для запуска главной требуется настроенный существующий API с опубликованными программами. Пустой каталог сохраняет существующее состояние; карусель не придумывает примеры. Не запускайте Telegram polling как часть визуальной проверки.

Самостоятельный HTML-предпросмотр находится в `artifacts/discipline-carousel/MyWaveTour_discipline_carousel.html`. Он включает изображения и код компонента, использует фактические названия из публичного каталога, прочитанные 2026-10-09, и открывает существующие ссылки программ. В стенде Next Link заменён обычным anchor; интеграция Next отдельно проверяется сборкой. Это визуальный стенд, а не копия каталога или доказательство production-деплоя.

## Docker и подготовка к деплою

Обычная воспроизводимая сборка для release выполняется из корня репозитория:

```powershell
docker build -f apps/web/Dockerfile -t tourism-web:discipline-carousel .
docker run --rm -p 127.0.0.1:4182:3000 tourism-web:discipline-carousel
```

Проверочный Docker-контекст находится отдельно в `artifacts/discipline-carousel/docker-context`; он не содержит `.env` или node_modules с Windows. QA использует существующий образ `tourism-miniapp-qa-web:local` (Node 20.20.2, Next 15.5.18, React 18.3.1), накладывает текущие исходники, устанавливает зафиксированные dev-зависимости и выполняет сборку пакетов и web. Это проверка совместимости с Linux/Docker, не готовый production release.

```powershell
docker build -f artifacts/discipline-carousel/docker-context/Dockerfile.qa -t tourism-discipline-carousel:verification artifacts/discipline-carousel/docker-context
docker run --rm -p 127.0.0.1:4182:3000 tourism-discipline-carousel:verification
```

Перед merge: зелёный CI на точном SHA PR. Перед деплоем: сборка release-образа штатным Dockerfile, ручная проверка выбора дисциплины на реальном API, проверка touch/reduced motion и сохранение текущего web-образа для отката. Backend, Telegram, БД, nginx, env, Compose и production в этой задаче не изменяются.

## Риски, откат и следующий шаг

Скульптуры — иллюстрации, а не модели оборудования конкретного организатора. Сложные/смешанные названия используют соответствующую общую фигуру; неизвестные не получают вымышленный спорт. Не реализованы новые дисциплины из референса, отсутствующие в данных, новый фильтр, изменение API и тяжёлая WebGL-сцена.

Откат: revert коммита слияния PR возвращает главную и удаляет добавленные presentation-файлы; до merge можно откатить отдельный коммит визуальной итерации. При будущем деплое переключить web обратно на сохранённый предыдущий образ; миграций и отката данных нет.

Следующий шаг: визуальное принятие, проверка на физическом телефоне и рассмотрение PR после CI.
