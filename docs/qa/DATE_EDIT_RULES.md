# Правила редактирования дат программы

## Источник истины

- Канонические границы поездки: **`startDate`** и **`endDate`** (обязательны в модели `Program`).
- **`durationDays`** — **производное поле**: считается только на сервере, не задаётся клиентом отдельно от дат.

## Формула

- Функция **`inclusiveDurationDaysUTC`** в пакете `@mywave/shared-types` (`programCalendar.ts`): календарные дни в UTC **включительно** (одинаковый день старта и конца → 1 день).
- Та же логика используется в API (`PATCH /programs/:id`, `POST /programs`), publish gate и предпросмотре админки.

## API

- **`PATCH /programs/:id`**
  - Тело **только** с `durationDays` (без `startDate`/`endDate`) → **400**, текст: `durationDays cannot be updated directly; provide startDate/endDate`, код `DURATION_READ_ONLY`.
  - Если в теле есть и даты, и `durationDays` → **`durationDays` игнорируется**, пересчёт по датам; факт игнорирования логируется на уровне `console.debug`.
  - При изменении любой из дат сервер подставляет вторую из текущей записи, валидирует `endDate >= startDate`, записывает новый `durationDays`.
- **`POST /programs`**: `durationDays` в теле не требуется; если передан — игнорируется (`debug`), длительность считается по датам.

## UX (админка)

- Редактирование длительности вручную отсутствует; показывается предпросмотр и предупреждение о влиянии на каталог и заявки.
- Изменения дат попадают в **audit log** (поля `startDate`, `endDate`, `durationDays` при пересчёте).

## Не делаем на этом шаге

- Уведомления гостям/организатору об автоматической смене дат — отдельный эпик.
