# Ответ команде mywavewake.ru: почему кемпы не проходят фильтры

**Кому:** команде сайта MyWave (mywavewake.ru)
**От:** MyWaveTour (Camp API)
**Дата:** 25.09.2026
**На письмо:** `Site_MyWave/docs/integrations/TOUR_TEAM_CAMPS_LETTER.md`

---

Здравствуйте!

Спасибо за подробное письмо. Коротко: обмен данными работает, и пустая витрина сейчас отражает реальное состояние каталога. Опубликованных вейк-кемпов у нас в данный момент нет (подробности в разделе 3). Попутно мы нашли ошибку пагинации на нашей стороне и одно расхождение в контракте. Их стоит учесть, чтобы кемпы корректно появились, когда будут опубликованы.

## 1. Поле `sport` — это список, а не строка

Сейчас API отдаёт `sport` массивом значений `wakesurf` / `wakeboard`:

```json
"sport": ["wakesurf"]
"sport": ["wakesurf", "wakeboard"]
```

Значения `mixed` у нас нет. Кемп с обоими видами приходит как `["wakesurf", "wakeboard"]`. Если витрина сравнивает `sport` со строкой, отсеивается каждый кемп. Предлагаем на сайте такое условие:

- `sport` — массив, пересекающийся с `{wakesurf, wakeboard}`, или пустой (у нас пустым он не бывает).

Остальные поля совпадают с вашей таблицей:

| Поле | Что отдаёт API |
|---|---|
| `publication_status` | `published` (в списке по умолчанию только они) |
| `content_rights_status` | `unknown`; `restricted` только у помеченных модератором |
| `audience_language` | всегда `["ru"]` (тоже массив) |
| `start_date`, `end_date` | всегда заполнены, формат `YYYY-MM-DD` |
| `id` | `tour_<id программы>`, тестовых префиксов нет |

## 2. Ошибка пагинации (исправлена)

Особенность «`limit=100` пустой, `limit=5` с данными» — это была наша ошибка. `next_offset` считался по числу кемпов после внутренней фильтрации, а не по строкам базы. Если на странице часть программ отсеивалась, `next_offset` становился `null`, и клиент прекращал листать раньше времени. Исправлено в релизе от 25.09.2026: теперь `next_offset = offset + limit`, пока в базе есть следующие строки. Страница может вернуть меньше `limit` элементов (даже 0) при ненулевом `next_offset`, поэтому листайте, пока `next_offset` не станет `null`. Размер страницы 25 подходит.

## 3. Что сейчас в каталоге

Отбор в Camp API: опубликованная программа, в названии, формате или аудитории есть «кемп / кэмп / лагерь / camp», а в дисциплине или названии есть вейксерф или вейкборд.

Проверка 25.09.2026 после релиза:

- `GET /api/v1/camps?limit=100` с вашим токеном возвращает `{"items": [], "next_offset": null}`, то есть HTTP 200, корректный JSON и пустой список;
- в базе нет ни одной программы по вейксерфу или вейкборду с датой окончания после 25.09.2026, в любом статусе.

Ответы на ваши вопросы:

1. Сейчас API отдаёт 0 кемпов, кемпов с датами после 25.09.2026 нет. Летний сезон закончился, а программы на следующий сезон в каталог ещё не поступали.
2. Примера JSON реального кемпа на будущие даты пока нет. Схема полей описана в разделе 1, пример формы:

```json
{
  "id": "tour_cmxxxxxxxxxxxxxxx",
  "title": "Вейксерф-кемп на Волге",
  "sport": ["wakesurf"],
  "start_date": "2027-06-10",
  "end_date": "2027-06-16",
  "publication_status": "published",
  "content_rights_status": "unknown",
  "audience_language": ["ru"],
  "cover_image_url": "https://mywavetour.ru/ingestion-media/....jpg",
  "booking_url": "https://..."
}
```

3. Особенность с `limit` была нашей ошибкой, она исправлена (раздел 2).

## 4. Наполнение на следующий сезон

Каталог пополняется автоматически из источников (Telegram-каналы и Instagram вейк-школ и организаторов) после модерации. Когда появятся опубликованные вейк-кемпы, они сразу придут в API, менять на вашей стороне ничего не нужно, кроме условия по `sport` из раздела 1. О сроках наполнения на сезон 2027 сообщим отдельно.

Со своей стороны сделайте, пожалуйста, две вещи: поддержите `sport` и `audience_language` как массивы и листайте до `next_offset: null`. Тогда витрина покажет кемпы без дополнительных правок. Если после появления данных какой-то кемп не отобразится, пришлите его `id`, проверим вместе.
